# النشر المجاني (InfinityFree) — خطوة بخطوة

نسخة العرض (معرض الأعمال) تُنشر بدون أي تكلفة: استضافة **InfinityFree** مع نطاق فرعي مجاني وشهادة SSL مجانية.
للنشر على استضافة مدفوعة ودومين خاص انظر [DEPLOY.md](DEPLOY.md).

## ما يختلف عن النشر المدفوع

| | النشر المدفوع | النشر المجاني |
|---|---|---|
| الدومين | دومين خاص | نطاق فرعي مجاني (مثل `nafha.great-site.net`) |
| الكاش | LiteSpeed Cache | بدون (الموقع خفيف أصلًا: CSS مدمج، jQuery في الفوتر، WebP) |
| الحماية | Wordfence + رابط دخول مخفي + Turnstile | **بدون Wordfence** (يستهلك حدود المعالج في الاستضافة المجانية ويسبب إيقاف الحساب) — يبقى رابط الدخول المخفي، Turnstile، كلمة مرور قوية عشوائية، حظر xmlrpc |
| النسخ الاحتياطي | UpdraftPlus إلى Google Drive | **بدون UpdraftPlus** — الكود في Git، وقاعدة البيانات تُعاد من `tools/deploy/build.sh` |
| الإيميلات | SMTP الاستضافة | Brevo المجاني (300 رسالة/يوم) + إضافة FluentSMTP المجانية |

حدود InfinityFree المهمة: 30,000 ملف (الموقع ~12,500)، رفع ملف واحد حتى 10 MB عبر مدير الملفات (لذلك نستخدم FileZilla)، وحد لعدد العمليات المتزامنة — مناسب لموقع عرض.

---

## الخطوة 1 — حساب الاستضافة (أنت)
1. سجّل في **infinityfree.com** (بدون بطاقة).
2. **Create Account** ← اختر **نطاقًا فرعيًا مجانيًا** (مثال: `nafha` + أحد النطاقات المتاحة).
3. من لوحة الحساب ← **SSL Certificates** ← اطلب شهادة للنطاق الفرعي وانتظر حتى تُثبَّت (الموقع يجب أن يعمل بـ `https://`).
4. أرسل لي الرابط النهائي (مثل `https://nafha.great-site.net`) والبريد الذي تريده للإدارة واستقبال الطلبات.

## الخطوة 2 — تجهيز الحزمة (أنا)
```bash
tools/deploy/build.sh https://النطاق [البريد]
```
تنتج في `dist/`:
- `nafha-site.zip` — ملفات الموقع كاملة.
- `nafha-db.sql` — قاعدة البيانات بالرابط الجديد (بدون جداول Wordfence، بدون جلسات أو بيانات مؤقتة).
- `deploy-credentials.txt` — اسم مستخدم المدير الجديد وكلمة مرور عشوائية قوية (احفظها في مدير كلمات المرور واحذف الملف بعد الدخول).

قاعدة البيانات المحلية لا تتغير: العمل يتم على نسخة مؤقتة تُحذف بعد التصدير.

## الخطوة 3 — قاعدة البيانات (أنت)
1. لوحة InfinityFree ← **MySQL Databases** ← أنشئ قاعدة بيانات.
2. سجّل: **اسم القاعدة**، **المستخدم**، **كلمة المرور** (كلمة مرور الحساب في **Account Details**)، و**المضيف** (مثل `sqlXXX.infinityfree.com`).
3. **phpMyAdmin** ← اختر القاعدة ← **Import** ← ارفع `nafha-db.sql` ← **Go**.

## الخطوة 4 — رفع الملفات (أنت)
1. فك ضغط `nafha-site.zip` على جهازك.
2. افتح `wp-config.php` وضع القيم الأربع من الخطوة 3 مكان `PUT_DATABASE_…_HERE`.
3. ثبّت **FileZilla** واتصل ببيانات **FTP Details** من لوحة الحساب.
4. افتح مجلد `htdocs` على الخادم واحذف الملفات الافتراضية فيه، ثم اسحب **محتويات** المجلد المفكوك (وليس المجلد نفسه) إلى `htdocs`. الرفع يأخذ وقتًا (~12,500 ملف)؛ إن فشلت ملفات أعد المحاولة من **Failed transfers**.

## الخطوة 5 — التشغيل والفحص (معًا)
1. افتح الموقع وتأكد من الرئيسية والمتجر وصفحة منتج.
2. ادخل من `https://النطاق/nafha-login/` بالبيانات من `deploy-credentials.txt`.
3. **الإعدادات ← الروابط الدائمة** ← **حفظ** (بدون تغيير) لتحديث الروابط.
4. أشغّل اختبارات المتصفح على الموقع الحي (للقراءة فقط، بدون إنشاء طلبات):
   ```bash
   (cd tools && NAFHA_URL=https://النطاق node e2e/i18n-scan.js)
   ```
5. أقيس السرعة على **pagespeed.web.dev**.

## الخطوة 6 — الخدمات المجانية الإضافية (معًا، واحدة واحدة)
| الخدمة | لماذا | أين تُضاف |
|---|---|---|
| **Cloudflare Turnstile** | حماية الدخول والتسجيل والمراجعات من الروبوتات | dash.cloudflare.com ← Turnstile ← Add site (النطاق الفرعي) ← الإعدادات ← Cloudflare Turnstile ← المفاتيح ← **Test Response** |
| **Brevo + FluentSMTP** | وصول إيميلات الطلبات (الاستضافة المجانية لا ترسل بريدًا) | brevo.com ← SMTP & API ← مفتاح SMTP؛ الإضافات ← أضف FluentSMTP ← Brevo |
| **Google Tag Manager + GA4** | معرفة عدد زوار المشروع ومصادرهم | انظر [TRACKING.md](TRACKING.md)؛ المعرّف في ووكومرس ← الإعدادات ← نفحة |
| **Google Search Console** | ظهور الموقع في جوجل | أضف النطاق ← تحقق عبر Rank Math ← أرسل `sitemap_index.xml` |

## التحديث لاحقًا
أي تعديل محلي يُرفع بإعادة الخطوات 2–4 (أو رفع الملفات المعدّلة فقط عبر FileZilla إن كان التعديل في الكود فقط).
تنبيه: استيراد `nafha-db.sql` من جديد يستبدل الطلبات والمراجعات التي تمت على الموقع الحي.
